# RAG 架构综述

检索增强生成（RAG）的标准管线分五段：文档接入 → 切分 → 向量化 → 检索 → 生成。工程质量的大头在切分与检索参数上，模型本身反而是最不容易出错的一环。

切分（chunking）：推荐起步参数 chunk_size 512 tokens、overlap 64 tokens。块太大稀释语义，太小丢失上下文；结构化文档优先按标题层级切，再按长度兜底。

检索：单一向量检索对关键词型查询（错误码、产品型号）偏弱，生产系统建议混合检索——BM25 稀疏检索负责精确关键词命中，向量稠密检索负责语义泛化，两路结果用 RRF 融合。BM25 无需向量化、零推理成本，是廉价且必要的一路。

两段式召回：向量召回 top-20，再经重排模型（reranker）精排后保留 top-5 送入生成；直接用大 top_k 会撑爆上下文窗口，直接用小 top_k 会漏掉关键证据。

生成与引用：提示词中每个证据块应带来源锚点（文档 ID + 位置），生成答案时逐句挂引用，便于人工核验与追溯。

评测：RAG 系统改动任何一环（模型、分块、检索参数）都应在固定题集上做回归，这正是独立评测支线的动机。
