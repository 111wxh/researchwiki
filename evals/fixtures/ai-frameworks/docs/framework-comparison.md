# 多框架对比：LangChain 与 OpenAI SDK 生态

LLM 应用开发有两大主流路线：以 LangChain 为代表的编排框架路线，与以 OpenAI SDK 为代表的托管服务路线。本篇在受控合成语料口径下给出横向对比。

能力侧重：LangChain 强在编排自由度——检索器、记忆、智能体组件可自由组合、可替换后端，适合多模型多库的复杂管道；OpenAI 路线强在托管省心——Assistants API 把工具循环、文件检索交给服务端，运维成本几乎为零，但深度定制要绕开托管层。

智能体能力量化：在受控合成基准 AgentBench-X 的工具调用套件上，LangChain Agents 得分 72.4，OpenAI Assistants 得分 75.1。后者胜在工具循环由服务端托管、状态管理更稳；前者胜在可完全离线自托管、后端可替换。

向量库选型结论（与各库篇互证）：十亿级向量首选 Milvus 这类分布式系统；百万级以下 FAISS 或 Chroma 已足够，不必过度设计。

迁移成本：两者在嵌入与结构化输出上接口语义相近，主要差异在记忆与检索器的抽象层——从 LangChain 迁往托管服务，通常要重写记忆模块。
