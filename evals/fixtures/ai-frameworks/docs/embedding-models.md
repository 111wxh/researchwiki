# 嵌入模型选型

嵌入选型看三个硬指标：检索质量、向量维度（决定存储与内存成本）、最大输入长度。本篇在受控合成语料口径下，给出两个代表模型的对比。

text-embedding-3-large：默认 3072 维，输入上限 8191 tokens，按量计费（定价见 Embeddings API 篇）。bge-m3：开源多语模型，输出 1024 维，最大输入 8192 tokens，可本地部署，无按量成本。

检索质量用自建中文基准 FixtureRAG-Bench（受控合成问答语料）评测：text-embedding-3-large 的 recall@10 为 0.84，bge-m3 为 0.81；差距主要出现在专业术语查询上，通用口语化查询两者接近。

选型经验：数据敏感、必须私有化部署时选 bge-m3 这类开源模型，且 1024 维的存储成本约为 3072 维的三分之一；追求极致召回、可接受外部 API 时选 text-embedding-3-large，并可用 dimensions 参数按需降维。混合策略也常见：冷数据用低维模型，热点库用高维模型。

评测提醒：recall 指标对分块参数敏感，换分块方案必须重测；分块口径见 RAG 架构综述篇。
