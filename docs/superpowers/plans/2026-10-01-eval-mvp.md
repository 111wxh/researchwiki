# 评测支线 MVP（PLAN §7.1–7.4：30 题 × 4 对照条件）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 P1–P3 的收益变成可信、可复跑的对照评测：受控语料 + 30 题 QA × 4 条件（无 Memory / Vector RAG / Hybrid RAG / External Memory warm），确定性指标 + LLM judge（glm-4.7），全链路 mock 可验证、real 可重跑、数字可从凭证重算。

**Architecture:** 新包 `src/researchwiki/evals/`（corpus 检索 / metrics / judge / rag harness）+ 仓库根 `evals/` 数据目录（qa 题集、fixtures 语料、results、reports）+ `scripts/run_eval.py`、`scripts/report_eval.py`。四个条件同语料同模型同题集：C1 无 Memory 走 AgentLoop 关记忆开关（每题一次性 root）；C2/C3 是独立检索-生成 harness（不走 agent loop）；C4 走完整 warm loop（seed 一次，每题 copytree 隔离）。LLM judge 独立槽位 `[llm.judge]`（glm-4.7）。

**Tech Stack:** Python 3.11+ / pytest / SQLite / httpx / uv。测试零真实网络；real run 需 `RESEARCHWIKI_*` key（.env 已配）。

**Spec:** `PLAN.md` §7.1–7.4（题集占比/对照条件/指标/产物）+ §8（证据四类）+ §4.1 风险表（Mock/Replay 开发、评测记录 provider、小样本标注）。

## Global Constraints

- **同口径**：四个条件同一生成模型、同一 embedding、同一题集、相同回答长度约束（统一"回答不超过 300 字"写进所有生成 prompt）。
- **受控语料口径**（本计划新增裁定，评测边界如实记录）：MVP 用自洽合成语料（AI 框架生态主题，`fixture://` URL，双版本时效文档），四条件从同一语料取材；provider 记录为 "fixture-corpus"；真实搜索 provider 后续只替换 `SearchProvider` 实现。
- **可复算**：所有结论引用原始 `tokens.jsonl`、`run-metrics.json`、逐题结果 JSONL；每个数字标样本数；不提交手工表格替代原始凭证。
- **诚实边界**：judge 输出解析失败记 error 不编造；无答案题的拒答判定用确定性启发式 + judge 双口径分别记录。
- **judge 强度**：`[llm.judge]` 用 glm-4.7（用户政策：judge 不能用 air）；`Tier` literal 扩 "judge"（5 处注解机械改）；测试用 ScriptedProvider 当 mock judge。
- **零网络测试**；`evals/` 数据目录不进 wheel（pyproject packages 不动，数据与代码分离：代码在 `src/researchwiki/evals/`）。
- 注释中文；git add 显式路径；conventional commits；逐交付 push（代理失联时 `git -c http.proxy= push` 回退）。
- **范围外**：条件⑤（External Memory + maintenance，等 P4）；~100 题扩展；真实搜索 provider；§7.5 开源交付。

**Interfaces:**
